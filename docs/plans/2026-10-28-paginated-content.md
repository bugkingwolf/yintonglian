# 案例与素材分页实施计划

目标：案例增长后不再一次加载全部详情或素材；保留既有界面与分享路径，各端统一使用分页接口。
架构：Go与GORM在SQLite中执行筛选、稳定排序、COUNT及LIMIT/OFFSET，列表只投影摘要字段，详情独立读取。官网路由按需请求，后台分页并按需编辑，随后小程序使用相同新接口。按用户要求删除旧全量接口，部署时同步安排小程序升级。

1. 新建查询模块，新增公开摘要分页、首页推荐、后台配置统计、后台案例及素材分页、后台单条案例接口。公开配置不再调用完整Snapshot。测试摘要脱敏、分页稳定、筛选、范围限制、草稿隔离及旧接口删除。
2. 官网保留地址栏筛选与返回历史，增加分页、加载中、错误重试、并发请求防串页。首页仅推荐，关于与平台仅配置，详情单独读取与相关摘要。图片懒加载、视频不预加载。
3. 后台案例与素材各自分页；编辑、复制、发布下架先取单条详情，统计与关联数服务端计算。素材选择器独立分页搜索，保留当前案例原素材。筛选及翻页更新接口，操作后保持页码并处理末页删除。
4. 使用新接口改小程序首页、案例筛选与触底分页、详情与相关案例；关于和平台不再请求案例。删除旧全量接口及处理函数，更新测试与文档。
5. 构造超过一页的隔离测试内容，验证翻页无重复漏项、过滤与详情一致、失败重试、快速切换不串页、编辑保留未显示字段。执行Go测试、前端测试及浏览器验证。未经用户指令不push或部署。
