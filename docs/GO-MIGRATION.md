# Node到Go的迁移说明

## 保留的契约

官网、后台、小程序页面与API路径不变。数据库使用原表结构与JSON字段；原有数据目录和附件保留。Cookie继续叫ytl_session，会话记录继续保存SHA256 Token摘要、CSRF和毫秒时间戳。

scrypt参数为N=16384、r=8、p=1、64字节结果；盐值使用原Node代码的十六进制文本，而不是先解码成字节。测试夹具由Node生成，仅包含合成测试凭据，不包含真实密码。

## Go代码组织

使用标准库net/http路由；数据访问层现已改用GORM，底层通过database/sql连接SQLite。纯Go SQLite驱动使CGO_ENABLED=0构建可用；服务器部署仍需public目录，不将前端文件全部嵌入二进制。

管理写请求加互斥保护，授权在进入临界区后重新读取会话；主推荐及密码变更使用事务。登录验证与密码修改使用认证锁，避免旧密码验证与新会话发放之间的竞态。

## 当前边界

本轮保留JSON payload表以减少迁移风险；已添加GORM，未进行关系化重构或多实例写入。管理写操作互斥适合单管理员，文件上传期间其他管理写操作会等待。大量并发或多实例场景需重新设计存储与分布式协调。

原Node后端与初始源码包移到工作目录留作回退，不混入新的交付包。Node只作为可选前端检查工具，Go服务启动、管理员初始化和备份都不依赖Node运行时。
