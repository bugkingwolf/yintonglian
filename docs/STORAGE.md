# 文件存储抽象

## 当前实现

`internal/app/storage.go` 定义 `FileStorage`：Put、Open、Stat、Delete。默认 `LocalFileStorage` 写入 配置项 data_dir 下的 uploads/，与原目录兼容，不需要迁移数据或修改数据库。Go服务使用 Config.FileStorage 注入其他实现；未注入时仍使用本地磁盘。

文件标识沿用 uploads.filename；作品、团队与资质中的地址仍是 /media/<文件标识>，不保存服务器IP或OSS绝对URL。PPT内置素材仍在 public/assets，是随代码部署的静态资源，不属于用户上传存储。

- 上传：私有临时文件流式接收、检查大小和文件头，之后调用Put。临时文件与目标文件复制阶段会短暂多占一份磁盘空间；不会将整个视频读入内存。
- 本地Put：在目标目录写临时文件、同步并原子重命名；中途失败不暴露半个文件。
- 访问：先做管理员/已发布引用鉴权，再调用Open并通过ServeContent提供Range和HEAD。
- 引用验证：通过Stat判断存储对象是否存在；仅不存在映射为无效素材，其他存储故障正常返回错误。
- 删除：检查案例、资质、全部团队成员的引用，然后调用Delete；不存在对象的删除是幂等操作。
- 数据库写入失败：删除已经写入的存储对象，避免遗留孤立文件。清理失败会同时报告两项错误。
- 备份：从存储接口逐个读取文件，导出为传统content.sqlite＋uploads目录，可直接恢复为本地存储；拒绝不完整文件复制。

本地文件使用os.Root限制访问范围，拒绝路径穿越及指向目录外的符号链接。

## 后续接OSS

本次没有引入OSS SDK、云账号凭据或收费服务。未来增加OSS实现及初始化配置后，通过Config.FileStorage注入即可接管持久文件的读写。Open需要提供可Seek的读取（例如通过Range实现），用于备份及代理交付。

远程存储还可实现可选的 `SignedMediaStorage`：SignedURL(ctx, key, method, lifetime)。鉴权通过后，/media端点以307跳转到签名HTTPS地址，客户端直接从OSS/CDN读取视频，避免占用ECS出网带宽；本地实现不启用此路径。GET/HEAD需分别签名，有效期为5分钟，禁止返回永久公开URL。已签发的链接在到期前可能仍然有效。

迁移时先复制原文件并保留filename作为对象键，核对数量与校验值，再切换实现。迁移工具、真实OSS实现、域名和签名策略仍需在接入OSS时完成，不能仅开通OSS就自动启用。

备份沿用维护窗口要求：进程内写锁不能阻止另一个服务实例更新文件。远程存储增加网络成本与备份时长，完整备份需要保留读取所有对象的权限。
